# Instructions for Maintaining the Changelog System

This document outlines the steps and best practices to ensure the changelog system is maintained consistently throughout the project.

## 1. Changelog Update Protocol

- **Pre-Response Hook**: The changelog must be updated before every response generated by the AI system. This is handled by the `WindsurfChangelogIntegrator.pre_response_hook` method.
- **Manual Updates**: For major releases, manually update the version and release date in the changelog.

## 2. Configuration Management

- The `config.ini` file contains settings for the changelog system. Do not commit sensitive data to this file.
- Adjust the `max_cache_size` in the `[state_manager]` section based on project size.

## 3. State Management

- The `StateManager` class is responsible for tracking changes. Ensure the cache directory (`.workspace_cache`) is included in `.gitignore`.
- Periodically clean the cache with the `cleanup_cache` method.

## 4. Workspace Scanning

- The `WorkspaceScanner` class scans the project directory. Update the `ignore_patterns` in its `__init__` method to exclude irrelevant files.

## 5. Change Classification

- All changes are classified as ADDED, MODIFIED, or REMOVED. Ensure the `_format_change` method in `ChangelogEngine` accurately represents each change.

## 6. Windsurf Integration

- The `WindsurfChangelogIntegrator` class hooks into the AI system. Verify that the `pre_response_hook` is called before generating responses.

## 7. Quality Assurance

- Regularly run the `validation_suite.py` (to be implemented) to ensure system integrity.
- Monitor performance metrics from `StateManager.get_metrics`.

By following these instructions, we ensure consistent and accurate changelog generation throughout the project lifecycle.
